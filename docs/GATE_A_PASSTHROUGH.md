# Gate A — Quest passthrough build

Software build completed on 2026-11-02 (Hong Kong). Hardware Gate A remains pending: no authorized headset was connected during this work.

## Scene and rendering baseline

XRFoundationSetup is an explicit batch-mode Editor tool in Assembly-CSharp-Editor. It creates new assets via Unity APIs, refuses to regenerate existing foundation assets, and never modifies the template scene. No new Runtime/Editor asmdef is needed for this milestone.

- Scene: Assets/BrickBloom/Scenes/XRFoundation.unity.
- Local prefab variant: Assets/BrickBloom/Prefabs/XR/QuestCameraRig.prefab, based on the installed Core 207 OVRCameraRig. Exactly one rig, OVRManager with Stage origin and passthrough enabled, one OVRPassthroughLayer and one enabled CenterEyeAnchor camera.
- Core 207 OVRPassthroughLayer.SyncToOverlay fixes the composition to Underlay internally. No obsolete Placement API is used.
- Camera: Solid Color, transparent black RGBA (0,0,0,0), HDR/post processing/shadows off, MSAA on, clipping 0.05–20 m.
- Quest_RPAsset / Quest_Renderer: Forward, intermediate texture Auto, HDR/terrain holes/shadows off, MSAA 4x, render scale 1.0. Original Mobile/PC renderer assets are retained unchanged.
- Existing Mobile quality tier points to Quest_RPAsset. Android already defaults to this tier; iPhone also shares it in the original template. No separate iOS target is being developed. Global pipeline and PC quality assignment remain unchanged.
- OpenXR Android was already SinglePassInstanced (serialized 1). Explicitly retain it and align the separate legacy PlayerSettings.stereoRenderingPath with Instancing. Enable MetaXRSubsampledLayout alongside existing Meta foveation.
- WorkbenchRoot has unit scale and a serialized diagnostic stage-relative pose (0, 0.78, 0.55) m. CubeRoot has a root 8 cm BoxCollider and separate blue URP Unlit visual. There is no grab interaction or Rigidbody in Gate A. This pose is a visible test fixture, not desk detection or the final repositioning system.
- QuestDevelopment overrides its scene list with XRFoundation only. BuildApk also supplies that explicit scene in BuildPlayerOptions. The global SampleScene list is preserved.
- Source Android manifest is generated by Core 207's OVRManifestPreprocessor when missing; existing manifests are never silently rewritten. This satisfies the SDK's GameActivity source-manifest rule as well as the final APK entrypoint.

Use a simple OVRCameraRig for Gate A. Add the Comprehensive Interaction Rig as a child of this existing rig for Gate B after hardware passthrough is confirmed; do not add another camera rig.

Official guidance: [Meta OpenXR render settings](https://developers.meta.com/vr/documentation/unity/unity-openxr-settings/), [Meta passthrough alpha/underlay](https://developers.meta.com/vr/documentation/unity/unity-customize-passthrough-passthrough-ar/). The installed OpenXR/Meta/URP sources are authoritative for the exact APIs used. A recommended rendering baseline does not prove either-eye output on hardware.

## Reproduce

Close any Editor using this project. Use Unity 6000.0.85f1, the committed packages-lock.json and active QuestDevelopment profile. Run from project root:

```powershell
$unity = 'C:\Program Files\Unity\Hub\Editor\6000.0.85f1\Editor\Unity.exe'
# First creation only; refuses to overwrite an existing scene/rig/pipeline:
& $unity -batchmode -nographics -buildTarget Android -projectPath (Get-Location).Path -executeMethod BrickBloom.Editor.XRFoundationSetup.CreateAndValidate -reportFile docs/validation/android-meta.json -logFile Logs/brickbloom-gatea-setup.log
# Build the checked-in scene, independently of the global scene list:
& $unity -batchmode -nographics -buildTarget Android -projectPath (Get-Location).Path -executeMethod BrickBloom.Editor.XRFoundationSetup.BuildApk -logFile Logs/brickbloom-gatea-build.log
# Recheck the existing scene and all registered non-ignored Meta tasks, including cooldown tasks:
& $unity -batchmode -nographics -buildTarget Android -projectPath (Get-Location).Path -executeMethod BrickBloom.Editor.XRFoundationSetup.ValidateSceneAndProject -reportFile docs/validation/android-meta.json -logFile Logs/brickbloom-gatea-validation.log
```

These methods exit Unity themselves; omit -quit. Windows GUI launch can return before completion; inspect logs and the generated report instead of treating shell return as build success. BuildApk performs scene/render/profile preflight and writes docs/validation/gate-a-build.json. APK and raw build/test logs remain ignored.

## Validation finding and generated files

The first APK built successfully, but its log contained a Required GameActivity warning despite a zero-Required CLI report. Investigation found that Core 207's public CLI uses the default two-minute cooldown and omits HeavyProcessing tasks from its report while they cool down. This is not a complete Required gate. AndroidXRSetup now invokes the verified internal UpdateTasks overload with bypassCooldown=true, without ignoring or fixing rules. Two extra tasks became visible (93 total with the scene open), exposing one Required source-manifest failure. Unity's packaged GameActivity was already correct; the SDK rule also requires Assets/Plugins/Android/AndroidManifest.xml. The missing file is created using OVRManifestPreprocessor.GenerateOrUpdateAndroidManifest(true), followed by full validation and an APK rebuild.

PlayerSettings Instancing serializes as 2 in Unity 6000.0.85f1. The new OculusRuntimeSettings preloaded asset is an SDK-generated runtime reference and is retained. The SDK removes unsupported Quest 1 during build; Quest 3 remains supported. QualitySettings serialization also adds Unity's Nintendo Switch 2 default entry; no Switch target is enabled. Mobile and PC pipeline asset contents remain unchanged.

URP's build-populated m_RuntimeSettings cache in the global settings asset and formatting-only GraphicsSettings changes are excluded from this commit and left locally. Unreferenced OVRBuildConfig, empty StreamingAssets metadata and SceneTemplateSettings editor defaults are also left locally and excluded; they can be regenerated. Automatic approval review rejected the combined restore/delete cleanup command with only "blocked by policy", so no cleanup deletion was performed. Original Cloud fields remain uncommitted.

The fresh cooldown-bypassed Android report explicitly evaluates 93 tasks, including GameActivity=true, with zero Required failures. Keep this diagnostic discrepancy visible; do not describe the build as warning-free. SDK shutdown/read-only installed SDK metadata diagnostics are also preserved in raw ignored logs.
