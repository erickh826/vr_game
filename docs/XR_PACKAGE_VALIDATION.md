## Automatic SDK changes and preservation

Import is not side-effect-free. Reviewed generated artifacts are retained with their Unity-generated GUIDs:

- Assets/XR: OpenXR package/editor settings, loader asset and XRGeneralSettingsPerBuildTarget.
- Assets/Oculus/OculusProjectConfig.asset and runtime/debugger/input-definition defaults under Assets/Resources.
- EditorBuildSettings config-object references, SDK-added UI/sample tags in TagManager and XRPackageSettings initialization marker.

MetaXRFeatureEnabler.cs in installed Core explicitly enables Meta feature groups for Standalone and Android in batch mode. This happened automatically. The generated XRGeneralSettingsPerBuildTarget initially has no build-target entries: feature group enabled and loader asset present do not prove the Android loader is assigned or initialized. Hand tracking/passthrough defaults also remain unconfigured.

OVREngineConfigurationUpdater.cs automatically changed Android preferred install location from 1 to Auto (0). The original PlayerSettings file was snapshotted before installation; after verification it is restored byte-for-byte to preserve the user's existing changes. The SDK may apply its preference again on a later Editor launch; handle that deliberately in the Android configuration task.

DevAgentSettings and OVRPlatformToolSettings assets and their metas are excluded from Git because they can hold local connection/authentication or publishing data. DevAgent is disabled in the generated defaults. No AI integration was implemented. The original four dirty paths are not included in the package milestone commit.
